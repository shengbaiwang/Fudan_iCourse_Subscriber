# Qwen3-ASR-0.6B 完整录音对照（2026-09-20）

最终决策：继续使用 SenseVoice，撤回 Qwen 实验接入，仅保留评估记录。现有 ASR 代码、依赖、配置和工作流不变。Qwen 有个别人名改善，也有专名退化、空输出和生成异常；CPU 耗时为基线的 **8.84 倍**，进程树峰值内存为 **4.75 倍**，不足以支持替换默认后端。

## 样本与运行条件

- 完整本地讲座录音《中国革命史研究的前瞻与回顾 黄道炫》，文件时长 **129 分 5.86 秒**，66,193,728 字节。原计划的 iCourse 课次因 WebVPN 获取的音频被截断而弃用，截断样本未纳入本报告。
- 输入 SHA256：`077b69e54712994eaf074645152343a34750b3716d42ff280ce7391da6695e80`。
- Apple M3、16 GiB 内存、macOS 26.6.2、Python 3.12.13、sherpa-onnx 1.13.8；两个模型均为 int8、CPU、4 个推理线程。
- 两端顺序运行于独立进程，使用同一文件、16 kHz 单声道 PCM 和相同 Silero VAD（静音阈值 0.8 秒、最长语音段 30 秒）。最终 **739 个 VAD 窗口完全一致**，覆盖的 VAD 语音区间合计 5,231.195 秒。
- 两端实际解码均为 **7,745.812 秒**，与媒体时长差 0.048 秒，通过完整文件检查。音频完整并不等于所有话语都被正确识别。
- 这是单次本机实测，未在 GitHub Runner 上复测。既有 ASR 文本和 AI 摘要只用于选样，不作为准确率真值；本次无人工逐句校对的参考转写。

## 漏句线索与生成异常

- 原始空输出：SenseVoice **0 / 739**，Qwen **11 / 739**。Qwen 的 11 个空窗口均为 **0.442–2.010 秒**，合计 **9.118 秒**；对应基线含“没”“好”“嗯”、日语单字和纯标点等。归一化后，10 个窗口是基线有字而 Qwen 无字，另 1 个基线也只有标点。**不能把这些直接称为漏了 11 句。**
- 没有找到“SenseVoice 至少 20 个归一化字符、Qwen 少于其 60%”的窗口；这只排除了本规则能发现的大幅缩短，不能证明 Qwen 无漏句。
- 反方向原始有 7 个大幅缩短窗口，其中 3 个由 Qwen 的无关续写造成；修复后剩 4 个，仍需结合原音区分基线漏识别和 Qwen 增写。
- Qwen 在 **08:14、44:27、122:34** 三个窗口，于 `<|endoftext|>` 后生成无关文字，包括完整英文标题或组织介绍。较长的文本因此不能直接算作内容补全。
- Qwen 原生日志出现 **1 次重复循环截断警告**，在约 113–119 分钟的进度日志之间；日志未提供精确片段定位。另在 **115:27.974–115:29.440** 输出了 `language Cantonese`，显示仍有协议文本泄漏。

未作人工逐句听校，因此不报告 CER、WER 或“确认漏句率”。当前证据不能证明 Qwen 在术语及漏句方面稳定优于 SenseVoice。

## 实验验证记录（未合入）

实验中曾验证一项 Qwen 输出边界保护：遇到 `<|endoftext|>` / `<|im_end|>` 后停止接收后续文字，并保留完整 `raw_text` 和 `metadata_tail_removed` 标志。处理只识别模型边界标记，不按语言、政治词、英文词或重复词删内容。该修复随实验接入一起撤回，未改变现有 SenseVoice 逻辑。

对完整实测保存的 **739 段原始输出**做离线回放：仅上述 **3 段**发生边界裁剪，其余 736 段及所有时间戳不变。实验版本的回归覆盖原始文本保留、边界裁剪、多语言保留和空窗口，当时全套 **139 项测试通过**。这些实验测试未保留，不代表当前仓库的测试数量。

上表性能和原始字符数来自修复前的完整模型推理。回放是纯文本修复验证，**不是第二次模型推理测速**；没有把回放当作新的完整验收。它未解决专名退化、短段空输出或原生重复循环，因此本次仍不通过默认切换。
